## 1. 项目定位

高校学生在校园生活中频繁产生二手物品交易需求，例如教材轮转、毕业离校清闲置、电子产品换代、生活用品低价转让等。现有 QQ 群、微信群交易方式存在信息碎片化、检索困难、信任机制弱、交易状态难追踪等问题；泛品类二手平台虽然功能完整，但缺少校园场景的轻量化体验和校内交易信任基础。

本项目设计并实现一套校园二手物品交易系统，普通校园用户通过同一个微信小程序完成浏览、购买、发布闲置、沟通、下单、模拟支付、面交和评价，整体模式参考闲鱼的买卖一体体验；管理员通过独立 Web 后台完成用户、商品、分类、订单、公告、求购、咨询和统计管理。

## 2. 目标与范围

### 2.1 产品目标

- 为校园用户提供清晰、可检索、可追踪的二手交易流程。
- 为普通用户提供低门槛的闲置发布、卖出订单处理和统一消息会话回复能力。
- 为管理员提供独立 Web 后台，完成审核、管理和统计。

### 2.2 用户角色

| 角色 | 使用端 | 主要目标 |
|---|---|---|
| 普通用户 | 买卖一体微信小程序 | 搜索浏览商品、立即下单、模拟支付、确认收货、评价、收藏、发布求购、咨询沟通、发布闲置、管理发布、处理卖出订单、处理退款、回复咨询；购买通过商品详情"立即购买"或在聊天中完成 |
| 管理员 | Web 后台 | 审核商品、管理用户/分类/公告/求购/咨询/订单、查看统计数据 |

### 2.3 范围内

- 买卖一体微信小程序，包含买入流程、卖出流程和个人中心。
- 独立 Web 管理后台。
- Spring Boot REST API。
- MySQL 数据库。
- 本地图片上传与静态资源访问。
- 模拟支付，不接入真实资金流。
- 商品审核、订单状态机、退款售后、消息中心、留言咨询、求购、公告、收藏、面交地址等核心流程。
- 可用于后续生成高保真原型的页面、字段、状态和跳转说明。

### 2.4 范围外

- 真实微信支付。
- 云存储、CDN、对象存储。
- 第三方 IM SDK。
- 复杂商业化运营后台、多租户后台、复杂 BI 分析后台。
- 物流 API 对接。
- 推荐算法和用户行为画像。
- 生产级消息推送。

## 3. 推荐技术方案

### 3.1 当前实现方案

| 层次 | 技术 | 说明 |
|---|---|---|
| 普通用户端 | 微信小程序原生 + 自定义 Apple/iOS 风格轻量组件 | 买卖一体，贴合校园移动交易场景和答辩演示 |
| 管理员端 | Vue3 + Element Plus | 表格、筛选、审核、统计页面实现效率高，展示效果专业 |
| 后端 | Java Spring Boot 3.x | 毕业设计常用技术，便于论文描述分层架构 |
| ORM | MyBatis-Plus | 降低 CRUD 成本，保留 SQL 与实体映射的可解释性 |
| 数据库 | MySQL 8.0 | 适合用户、商品、订单等关系型业务 |
| 鉴权 | JWT + RBAC | 支持普通用户、管理员两类权限隔离；卖出能力属于普通用户功能集合 |
| 图片存储 | 本地文件系统 `/uploads` | 演示环境稳定，不依赖云服务 |
| 支付 | 模拟支付 | 点击确认付款后改变订单状态，不产生真实资金流 |
| 测试 | JUnit + MockMvc + Spring Boot Test | 与 Java 技术栈一致 |

### 3.2 技术方案

采用 Spring Boot + MyBatis-Plus。

### 4.1 小程序 UI/UX 规范

普通用户小程序采用 Apple/iOS 清爽校园 C2C 体验，设计目标是降低交易门槛、突出真实商品内容、强化校内可信交易，并减少后台化操作感。设计稿优先级高于通用移动端经验，具体规范以根目录 `DESIGN.md` 为准。

| 页面/组件 | 信息结构 | 交互规范 | 视觉规范 |
|---|---|---|---|
| 商品流卡片 | 真实商品图、成色标签、标题、红色价格、校区/取货点、发布者、认证标、收藏数 | 点击卡片进入详情；收藏等次要操作弱化 | 双列白底大圆角卡片，图片优先，浅灰背景和柔和阴影；不得使用纸张纹理、胶带或微旋转效果 |
| 搜索与筛选 | 关键词、分类、价格区间、成色、排序 | 首页搜索框与筛选按钮横排；分类/状态使用横向胶囊或底部筛选面板；筛选完成 Toast 反馈 | 白底胶囊搜索框，蓝色激活态；不直接暴露粗糙原生下拉作为主要视觉控件 |
| 商品详情 | 图片轮播、价格、标题、成色、面交地点、描述、发布者、校内面交保障、相关推荐 | 底部固定操作栏包含收藏、聊一聊、立即购买；不设购物车，购买直接通过“立即购买”或在聊天中完成 | 顶部大图圆角轮播；信息分区白色大卡；价格红色最高优先级；购买按钮为蓝色胶囊 |
| 发布入口 | 发布闲置、发求购、最近草稿、发布规则 | 底部一级导航“发布”进入动作选择页；优先展示“发布闲置”和“发求购”两个主入口 | 发布页为动作分流，不直接堆叠长表单；闲置入口使用蓝色语义，求购入口使用绿色语义 |
| 订单/支付 | 商品行、状态、金额、面交地点、约定时间、联系人、面交提醒、会话付款卡 | 确认面交页提交后生成待付款订单；待付款支持订单详情付款和聊天内付款；不设购物车 | 信息行采用线性图标 + 标签 + 右侧值 + chevron；底部固定栏展示合计和蓝色提交/付款按钮 |
| 发布表单 | 图片、标题、分类、价格/预算、成色、取货点、描述 | 分组填写，选择优先于手输；底部主按钮提交 | 延续白色大圆角分组卡；输入框和选择项使用 iOS 风格胶囊/信息行；异常通过字段提示或 Toast 表达 |
| 消息/聊天 | 头像、昵称、认证标、关联商品/求购/订单、最新消息、时间、缩略图、未读数；聊天气泡、订单卡和底部输入栏 | 点击进会话，长按置顶/删除；输入栏仅文字、表情、`+` 附件；待付款订单可在会话中展示付款卡片 | 会话列表为大卡内行列表；自己消息浅蓝气泡，对方消息白色气泡；订单付款按钮为蓝色 |
| 我的/卖出入口 | 头像、认证标签、学院校区、买入/发布/卖出/求购统计、交易记录、我的发布、个人资料 | 卖出能力集成在“我的”路径，不表现为独立后台 | 个人资料大卡 + 四列统计 + 分组列表卡；图标为彩色线性 iOS 风格 |

全局规则：

- 小程序以浅灰页面底、白色大圆角卡片、弱边框、柔和阴影和 iOS 固定栏为主。
- 主操作、选中态和底部导航激活态使用蓝色；绿色用于认证、成功、安全和求购辅助语义；红色用于价格、预算、合计金额和风险金额；不使用黄色作为主操作色。
- 每个页面只保留一个明确主操作；次要操作使用图标、轻按钮、长按菜单、更多入口或底部操作栏。
- 首页、求购、发布、消息、我的属于底部一级导航页面，不展示返回按钮，也不在右上角重复放置发布类按钮。
- 发布求购、发布闲置、确认订单、订单详情、聊天、地址、评价、发货、退款等二级流程隐藏底部导航，只保留顶部返回和当前流程主操作。
- 同一动作在同一页面只保留一个强入口：发布相关动作统一收口到一级导航“发布”；求购页可在 Banner 中提供“发求购”主入口；个人中心不重复强化消息中心入口。
- 页面不展示“异常态说明卡”“验收说明卡”等答辩注释型内容；空态、异常和规则通过轻提示、Toast 或空状态表达。
- 所有触控热区不小于 44px，底部导航最多 5 项。

## 6. 业务流程与状态机

### 6.1 商品审核流程

```
草稿 -> 待审核 -> 已上架 -> 已下架
          |          ^
          v          |
      审核不通过 -> 修改重提
```

规则：

- 普通用户提交商品后进入待审核。
- 管理员通过后商品进入已上架，可被其他用户搜索和购买。
- 管理员驳回时必须填写审核原因。
- 审核不通过商品可修改后重新提交。
- 已上架商品可由发布者下架，已下架商品不可购买。

### 6.2 订单状态流程

```
待付款 -> 待发货 -> 待收货 -> 已完成
  |                         |
  v                         v
已取消                  售后中 -> 退款完成/恢复已完成
```

规则：

- 创建订单后为待付款。
- 模拟付款后变为待发货。
- 发布者发货后变为待收货。
- 买方确认收货后变为已完成。
- 仅待付款订单可取消，取消后恢复商品为可售。
- 售后中订单由发布者处理，同意退款后恢复商品为可售，拒绝后恢复已完成或待收货状态。

### 6.3 消息与留言咨询流程

1. 普通用户可从商品详情“联系发布者”、求购详情“联系发布人”和底部导航“消息”进入咨询流程。
2. 系统按会话聚合商品咨询和求购咨询，消息列表仅展示头像、昵称、最新消息摘要、时间戳和关联商品/求购缩略图，最新消息超过一行截断。
3. 消息列表不提供批量操作、常驻删除按钮、常驻标记已读按钮或复杂筛选；点击会话进入聊天，长按会话可置顶或删除，操作完成后 Toast 反馈。
4. 聊天页采用气泡对话，自己消息靠右并使用浅蓝气泡，对方消息靠左并使用白色气泡；页面顶部展示对方昵称，消息流上方展示关联商品/求购/订单卡片。
5. 聊天页底部输入栏仅包含文字输入、表情和 `+` 附件三个入口；附件仅支持图片和相机，避免红包、位置、文件等非必要功能。
6. 当会话关联订单处于待付款状态时，聊天页可展示待付款订单卡片，包含商品摘要、金额、状态和“去付款”按钮；付款按钮触发模拟支付，不产生真实资金流。
7. 商品发布者或求购发布人可在同一小程序内回复咨询，发送成功后消息进入会话并显示轻提示。
8. 管理员可在 Web 后台删除违规咨询，删除后小程序消息中心保留会话异常提示“违规消息被删除”。
9. 当商品已下架、求购已删除或对方账号被禁用时，会话保留但禁止继续发送，并在输入栏上方展示禁用原因。

消息模块视觉与交互规范：

| 页面 | 信息结构 | 交互规范 | 视觉规范 |
|---|---|---|---|
| 消息列表 | 头像、昵称、认证标、最新消息、时间戳、商品/求购缩略图、未读数、状态标签 | 点击进入聊天；长按置顶/删除；Toast 反馈 | 白色大圆角列表卡；头像 48px；昵称 16px/600；消息正文 15px；辅助文字 12px；筛选激活态使用蓝色胶囊 |
| 聊天详情 | 顶部昵称、关联商品卡、待付款订单卡、消息气泡、底部输入栏 | 发送文字；表情入口；`+` 附件入口仅支持图片/相机；待付款订单支持会话内付款 | 自己气泡浅蓝；对方气泡白色；付款卡强调红色金额与蓝色“去付款”按钮；正文 15px；时间 12px |
| 异常状态 | 商品下架、账号禁用、违规删除 | 禁用输入栏，展示原因提示 | 灰色提示条，避免弹出复杂弹窗 |

### 6.4 求购流程

1. 普通用户可从底部导航“求购”、一级导航“发布”中的“发求购”、搜索无结果引导、商品详情“想要类似商品”等入口进入求购流程。
2. 求购入口默认进入求购大厅列表，不直接展示发布表单；普通用户需要发起需求时，通过求购页 Banner 中的“发求购”主按钮、一级导航“发布”动作分流页或空态按钮进入发布求购二级页，不在右上角重复放置同一动作。
3. 求购大厅展示求购标题、预算区间、成色要求、发布人、发布时间、校区/自提方式、简短描述和状态，并提供搜索框与横向分类胶囊。
4. 发布求购二级页展示移动端分组表单，价格由最低金额和最高金额选择生成预算区间，成色要求使用胶囊单选，提交成功后回到求购大厅。
5. 普通用户可查看求购详情或联系求购发布人。
6. 管理员可在 Web 后台删除违规求购，删除后小程序不再公开展示。

### 6.5 校园发货与交接规则

1. 卖出订单发货方式支持“当面交易/无需物流”和“快递/物流单号”。
2. 选择当面交易时，物流单号可为空，但取货地点、取货时间或交接说明必填。
3. 选择快递发货时，物流单号必填。
4. 发货成功后订单进入待收货，买方可在订单详情查看发货信息。

## 8. API 设计

### 8.1 通用约定

- API 前缀：`/api`
- 认证方式：`Authorization: Bearer <token>`
- 返回结构：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

- 常见错误码：

| code | 含义 |
|---|---|
| 0 | 成功 |
| 400 | 参数错误 |
| 401 | 未登录或 token 失效 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 409 | 状态冲突或商品已售出 |
| 500 | 系统异常 |

## 10. 非功能需求

### 10.1 性能

- 商品列表接口在 2 秒内返回。
- 商品详情接口在 1 秒内返回。
- 订单提交接口在 2 秒内完成状态校验和订单创建。
- 答辩演示环境支持 20 个并发用户访问，不出现超卖。
- 图片单张限制 2MB，最多 9 张。

### 10.2 安全

- 使用 JWT 做登录态管理。
- 使用 RBAC 限制普通用户、管理员权限；普通用户只能管理本人发布、购买和卖出的数据。
- 禁用用户不可登录、发布商品或下单。
- 上传文件限制类型为 JPG、PNG、WEBP。
- 手机号等敏感信息在后台列表中部分脱敏展示。
- 管理员审核、禁用、删除等关键操作记录操作时间和操作人。

### 10.3 兼容

- 小程序端支持微信开发者工具和微信小程序基础库 2.30 及以上。
- Web 后台支持 Chrome、Edge 最新两个主版本。
- 后端支持本地开发机运行，数据库使用 MySQL 8.0。

### 10.4 可用性

- 所有表单必填项需要前端提示和后端校验。
- 列表页提供加载态、空状态、错误状态。
- 删除、禁用、驳回、退款等高风险操作需要二次确认。
- 状态变化后页面需要立即刷新或给出明确反馈。

## 11. 测试方案

### 11.1 测试重点

- 商品审核流程：提交、通过、驳回、修改重提、上架、下架。
- 订单状态机：待付款、待发货、待收货、已完成、取消、售后、退款。
- 商品状态一致性：多人同时购买同一商品时保证状态正确切换。
- 权限控制：普通用户和管理员不可越权访问接口，普通用户不可管理他人发布或订单。
- 表单校验：价格、手机号、图片大小、必填字段。

### 11.2 测试层次

| 层次 | 覆盖范围 | 工具 |
|---|---|---|
| 单元测试 | 状态机、价格计算、参数校验 | JUnit |
| 接口测试 | REST API 正向与异常路径 | MockMvc |
| 集成测试 | 下单、支付、发货、收货、评价、咨询、求购完整链路 | Spring Boot Test |
| 原型验收 | 页面字段、跳转、状态、空态、异常态 | 人工走查 |

### 11.3 核心验收场景

1. 普通用户浏览商品并搜索目标商品，搜索无结果时可进入求购。
2. 普通用户发布商品，管理员审核通过。
3. 普通用户从商品详情联系发布者，并在消息中心查看会话。
4. 普通用户从商品详情立即下单提交订单。
5. 普通用户在订单详情或消息会话内完成模拟支付，发布者选择当面交易或快递发货，买方确认收货。
6. 普通用户评价订单并收藏商品。
7. 普通用户发布求购、查看求购详情、联系发布人，管理员删除违规求购或咨询。
8. 管理员禁用用户，被禁用用户无法登录。
9. 多人同时购买同一商品，系统只允许一个订单成功。
